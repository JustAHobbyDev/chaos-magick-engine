# Evaluation rubric v0.2

Preserve the [v0.1 rubric](rubric.md) and [baseline](baseline-results.md). Assess candidate validity before discovery. Never report a combined total or a passing novelty score. Reference specific output sections and compare literal mechanisms, not labels. A safe conventional result can pass every gate and fail the generative objective.

## Validity gates

Report pass/fail for each gate, with evidence. An unresolved premise can pass calibration only if the dependent path is held or explicitly conditional; it cannot pass as an execution-ready recommendation. Any gate failure invalidates that candidate. Report run-level failures separately, so one rejected candidate does not invalidate every survivor.

| ID | Pass requires |
| --- | --- |
| G1 | Observable endpoint preserved; vehicles and proxies kept distinct |
| G2 | Every hard constraint retained or explicitly branched; a relaxed branch never counted as original success |
| G3 | No invented material evidence, research, execution or source |
| G4 | No deception, coercion, prohibited access or unauthorized action endorsed |
| G5 | Facts, interpretations, assumptions and unknowns remain distinguishable |
| G6 | No activity or proposed experiment substituted for outcome or actual partial advance |
| G7 | A decisive premise tested before expensive construction is recommended |
| G8 | External cooperation not guaranteed; execution-ready paths have supported decision edges |

## Discovery profile

Score each dimension 0, 1 or 2 with an output reference. Shared anchors: 0 absent, duplicated or contradicted; 1 explicit but incomplete/provisional; 2 materially useful and evidenced at the claimed level. Use N/A only when a dimension has no target (for example salvage with no inadmissible proposal, or discovery in direct/impossible controls). Explain N/A; do not turn it into full credit. Do not sum these dimensions.

| ID | Dimension | Specific evidence for 2 |
| --- | --- | --- |
| D1 | Representation diversity | Distinct causal models explain the same observations and reveal different solution regions |
| D2 | Discriminating power | Bounded observation has contrasting predictions and a decision rule |
| D3 | Functional novelty | Literal mechanism absent from ordinary baseline AND supplied seeds; separately record whether v0.1 already found it |
| D4 | Structural distance | Concrete change to actors, relations, resources, sequence or institutional boundary |
| D5 | Advantage rationale | Explains why changed structure improves cost, odds, risk or information, with premise limits |
| D6 | Causal closure | Required edges supported, or exact partial transition solved without implying unresolved edges closed |
| D7 | Frontier advancement | Evidence changes reachability, uncertainty, reusable resources or justified pruning |
| D8 | Partial-bridge quality | Exact before/after, evidence, remaining gates, costs, portability and actual/proposed/conditional status |
| D9 | Mechanism salvage | Advantage extracted safely and permissible replacement independently verified at claimed level |
| D10 | Remote-domain/vocabulary expansion | Traceable discovery of terminology/mechanism changes the model or candidate; source limits explicit |
| D11 | Portability/option value | Specific reuse across paths with cost, permission and expiry limits |
| D12 | Resistance to generic advice | Recommendations change causal structure or choose sufficient direct route, without renamed repetition |
| D13 | Calibration/evidence discipline | Claims, proposed tests and observations distinguished; unknowns change verdicts |

A new mechanism with unknown feasibility may earn provisional novelty but is not a validated discovery. Merely giving a known mechanism a paradigm name earns zero novelty. A better table or more complete frontier can improve auditability without expanding reachability. A proposed partial bridge earns no actual-advance credit until its defining transition has changed.

## Comparative procedure

Freeze ordinary, archived unmodified v0.1 and v0.2 prompt bytes and fixture bytes before runs. Use each full prompt followed by the full unmodified fixture, recording exact assembly order/separator and hashes. For each substantive case preserve all three raw outputs before scoring. Run the unchanged direct and impossible controls too. Do not silently replace the old baseline with new v0.1 applications.

Prefer fresh conversations and a separate evaluator; shuffle opaque output IDs before scoring when meaningful blinding is feasible. If the same model authors, runs or scores, disclose shared context, seed exposure and order effects. Relabeling recognizable outputs is not blinding. Record exact known model identity, tool availability and use, access dates, source limits, unperformed experiments, deviations, and output hashes. Hashes reproduce artifacts, not stochastic outputs or evolving web pages.

Compare mechanisms and actual state changes case by case before looking at profiles. Record every validity gate, all discovery dimensions, control correctness/length, protocol conformance, and attention costs. Inspect external-decision gaps even when labeled conditional. No repeated fixture tuning. If outputs fail format requirements, preserve and report that failure; do not rewrite them to match the rubric.

Stop and report failure if comparisons show no meaningful improvement, paradigms only rename ordinary advice, all outputs repeat seeds, progress is confused with activity, cooperation is hidden, salvage is omitted, or length costs more attention than the decision gains. An inspectable revision plus honest negative comparative evidence satisfies the engineering task, not a claim that the creative engine works.
